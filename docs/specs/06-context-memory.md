# Context 与 Memory

## 1. 三层记忆

### Session Context
秒级/分钟级：当前订单、最近商品、当前客户、当前对话。

### Store Memory
长期：默认单位、商品别名、常用操作、价格习惯。

### Customer Memory
长期但可撤销：常用商品、历史价格、交付偏好。

## 2. 事实优先级

```text
Ledger/DB Fact > Current Context > Confirmed Memory > Inferred Memory
```

推断记忆不得覆盖事实。

## 3. 记忆写入

只有以下情况允许写长期记忆：
- 用户明确说“以后都这样”
- 用户确认系统建议的规则
- 可重复观察且达到阈值的稳定模式，并保留 source/confidence

## 4. 消歧

多个候选时：
- 低风险查询可以展示候选
- 钱/库存/客户对象写操作必须唯一解析或确认

## 5. 上下文窗口

不要无限累积聊天记录。只保留：
- 当前任务相关事实
- 最近 N 个业务对象
- 最近成功 Tool result 摘要
- 未完成的确认请求

## 6. 举例

老板：“还是昨天的价格。”

解析顺序：
1. 当前商品上下文
2. 昨日 price_history
3. 若只有一个有效价格 → 建议
4. 若多个价格 → 反问

禁止猜测。
