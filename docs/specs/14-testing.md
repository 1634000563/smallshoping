# 测试策略

## 1. 四层测试

### Domain Unit
金额、库存、会员、欠款、单位换算、成本。

### Repository/DB
事务、迁移、重建 Ledger、幂等。

### Integration
扫码→销售→支付→库存。

### End-to-End
真实 Android 设备关键旅程。

## 2. 账务关键不变量

- 销售完成后库存正确
- 退款后库存/支付/会员关系正确
- 会员余额可重建
- 客户欠款可重建
- 重复请求只执行一次
- 崩溃恢复不产生半笔交易

## 3. Offline Matrix

| 场景 | 无网 |
|---|---|
| 扫码销售 | 必须 |
| 称重销售 | 必须 |
| 采购 | 必须 |
| 会员消费 | 必须 |
| 报表 | 必须 |
| 云 AI | 不要求 |
| 云备份 | 不要求 |

## 4. 性能目标

- 本地常用查询目标 < 200ms
- 本地结账目标 < 500ms
- AI 请求不得阻塞本地 DB 事务

这些是工程目标，需在真机压测中验证。

## 5. 故障注入

必须模拟：
- 写事务后进程被杀
- 网络中断
- AI 返回非法 JSON
- 用户重复点确认
- 重复扫描同商品
- 数据库迁移失败
