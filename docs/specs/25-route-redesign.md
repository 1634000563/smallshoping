# V1 路线重构：难点优先 / AI 原生 Vertical Slice

## 决策

V1 不以传统业务模块为主要开发顺序；改为以高风险假设和用户任务为中心。

## 原因

最可能导致返工的部分是：上下文、记忆、Intent、Tool、风险、账本一致性以及跨行业实体模型。它们一旦后置，会迫使前面的 UI 与 Domain 重构。

## 新顺序

```text
最小账本
+ 最小商品
+ 最小 Context
+ Intent/Tool/Risk
→ 卖两斤土豆
→ 查今日销售
→ 进100斤土豆
→ 会员充值
→ 长期记忆
→ 五金/生鲜压力测试
→ UI/设备/迁移/支付/发布
```

## 不代表什么

这不是不要传统 Domain/数据库，而是不先建一个“传统 POS 用户工作流”。确定性 Domain/Ledger 仍然是基础，只是通过 Vertical Slice 被验证。
