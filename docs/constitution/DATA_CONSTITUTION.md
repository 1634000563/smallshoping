# 数据宪法

1. 数据库是 V1 本地事实源；Ledger 是库存、会员余额、客户欠款等可审计事实源。
2. 金额不得使用 Float/Double；使用最小货币单位整数或明确 Money 类型。
3. 数量必须带 Unit；称重商品不得把“斤、kg、g”当普通字符串混用。
4. 所有库存变化必须产生库存流水；禁止直接覆盖库存余额作为唯一事实。
5. 所有会员资金变化必须产生会员资金流水。
6. 所有客户欠款变化必须产生应收/回款流水。
7. 写操作必须事务化，并具有幂等键或等价去重机制。
8. 历史业务事实默认追加，不允许静默覆盖；纠错应通过反向流水/修正单记录。
9. 所有核心实体必须带 store_id；涉及设备和操作主体时保留 device_id/operator_id。
10. 数据迁移必须有 schema version，并提供可测试的 migration path。
11. 可以由 Ledger 重建派生余额；缓存余额不能成为唯一真相。
